<h2 id="probability-of-completion">Probability of on-time completion</h2>

The critical path gives a single expected duration. Committing to a date needs more: how likely
is it that the project actually finishes by then?

The classical PERT answer sums variances along the critical path — legitimate for independent
activities, since variances of independent quantities add — and appeals to the central limit
theorem to treat the total as normal:

$$
\sigma^2_{\text{project}} = \sum_{i \in \text{critical path}} \sigma_i^2,
\qquad
Z = \frac{D - T_e}{\sigma_{\text{project}}}
$$

where $D$ is the target date and $T_e$ the expected duration.

<PythonCell label="The classical PERT probability">
{`import numpy as np
import pandas as pd
from scipy import stats

network = pd.DataFrame([
    ("A", "Requirements gathering", "",     4,  6, 10),
    ("B", "Data model design",      "A",    3,  5,  9),
    ("C", "API design",             "A",    2,  4,  8),
    ("D", "Backend services",       "B,C",  8, 12, 22),
    ("E", "Frontend application",   "C",    6, 10, 16),
    ("F", "Data migration",         "B",    5,  8, 15),
    ("G", "System integration",     "D,E",  3,  5, 11),
    ("H", "Testing",                "F,G",  4,  7, 13),
    ("I", "Documentation",          "E",    2,  3,  6),
    ("J", "Launch",                 "H,I",  1,  2,  5),
], columns=["code", "name", "predecessors", "a", "m", "b"])

network["te"] = (network["a"] + 4 * network["m"] + network["b"]) / 6
network["variance"] = ((network["b"] - network["a"]) / 6) ** 2

duration = dict(zip(network["code"], network["te"]))
variance = dict(zip(network["code"], network["variance"]))
predecessors = {
    row["code"]: [p for p in row["predecessors"].split(",") if p]
    for _, row in network.iterrows()
}
successors = {code: [] for code in duration}
for code, parents in predecessors.items():
    for parent in parents:
        successors[parent].append(code)

def schedule(durations):
    order, remaining = [], {n: set(v) for n, v in predecessors.items()}
    while remaining:
        ready = sorted(n for n, v in remaining.items() if not v)
        order.extend(ready)
        for n in ready:
            del remaining[n]
        for v in remaining.values():
            v.difference_update(ready)

    finish = {}
    for code in order:
        start = max((finish[p] for p in predecessors[code]), default=0.0)
        finish[code] = start + durations[code]
    return order, finish

order, finish = schedule(duration)
project_duration = max(finish.values())

# Recover the critical path by walking back from the finish.
critical, node = [], max(finish, key=finish.get)
while True:
    critical.append(node)
    if not predecessors[node]:
        break
    node = max(predecessors[node], key=lambda p: finish[p])
critical.reverse()

path_variance = sum(variance[c] for c in critical)
path_sd = np.sqrt(path_variance)

print(f"critical path        {' -> '.join(critical)}")
print(f"expected duration    {project_duration:.2f} days")
print(f"path variance        {path_variance:.4f}")
print(f"path sd              {path_sd:.4f} days")

print()
print(f"{'target':>8}{'Z':>9}{'P(on time)':>13}")
for target in [40, 45, 48, 50, 52, 55, 60]:
    z = (target - project_duration) / path_sd
    print(f"{target:>8}{z:>9.3f}{stats.norm.cdf(z):>13.2%}")

print()
for confidence in [0.50, 0.80, 0.90, 0.95]:
    date = project_duration + stats.norm.ppf(confidence) * path_sd
    print(f"  {confidence:.0%} confident of finishing within {date:.1f} days")`}

<Callout title="The classical calculation is optimistic" variant="pitfall">
  <p>
    It considers only the critical path, and ignores that a <em>near</em>-critical path can
    overrun and become the binding one. With several paths of similar length, the probability that
    <em>all</em> of them finish by the target is lower — often much lower — than the probability
    that the critical one does. The correction is simulation, and the gap is usually startling.
  </p>
</Callout>

<PythonCell label="Simulation tells a different story">
{`import matplotlib.pyplot as plt

rng = np.random.default_rng(73)

def pert_beta(a, m, b, lam=4.0):
    mean = (a + lam * m + b) / (lam + 2)
    alpha = ((mean - a) * (2 * m - a - b)) / ((m - mean) * (b - a)) if m != mean else 3.0
    beta = alpha * (b - mean) / (mean - a)
    return stats.beta(alpha, beta, loc=a, scale=b - a)

distributions = {
    row["code"]: pert_beta(row["a"], row["m"], row["b"])
    for _, row in network.iterrows()
}

trials = 20_000
finishes = np.empty(trials)
critical_counts = {code: 0 for code in duration}

for trial in range(trials):
    sampled = {code: float(dist.rvs(random_state=rng)) for code, dist in distributions.items()}
    _, trial_finish = schedule(sampled)
    finishes[trial] = max(trial_finish.values())

    node = max(trial_finish, key=trial_finish.get)
    while True:
        critical_counts[node] += 1
        if not predecessors[node]:
            break
        node = max(predecessors[node], key=lambda p: trial_finish[p])

print(f"{'target':>8}{'PERT formula':>15}{'simulation':>13}{'difference':>13}")

    simulated = (finishes <= target).mean()
    print(f"{target:>8}{formula:>15.2%}{simulated:>13.2%}{simulated - formula:>+13.2%}")

print()
print(f"expected duration, formula     {project_duration:.2f} days")
print(f"expected duration, simulation  {finishes.mean():.2f} days")
print(f"simulation sd                  {finishes.std(ddof=1):.2f} days "
      f"(formula said {path_sd:.2f})")

print()
print("How often is each activity on the critical path?")

    share = critical_counts[code] / trials

<h2 id="crash-costs">Crash cost per day</h2>

**Crashing** is spending money to shorten an activity — overtime, contractors, parallel work.
Each activity has a normal duration and cost, a minimum achievable ("crash") duration, and a cost
at that minimum. The **crash cost per day** is

$$
\text{cost per day} = \frac{C_{\text{crash}} - C_{\text{normal}}}{t_{\text{normal}} - t_{\text{crash}}}
$$

Two rules govern which activity to crash:

1. **Only critical activities.** Shortening one with slack changes nothing.
2. **Cheapest first.** Among critical activities, crash the lowest cost per day.

<h2 id="what-to-crash">Choosing what to crash</h2>

The subtlety is that crashing changes the critical path. Shorten it enough and a previously
near-critical path becomes binding — after which you must shorten **both** paths simultaneously to
gain another day, at their combined cost.

    current[cheapest] -= 1.0
    crashed[cheapest] += 1.0
    total_cost += crash_data.loc[cheapest, "cost_per_day"]

    _, after = schedule(current)
    gained = current_duration - max(after.values())
    print(f"step {step + 1:>2}: crash {cheapest} by 1 day "

The final table is how crashing decisions should actually be made: not "how fast can we go?" but
"where does the total of crash cost plus delay cost bottom out?" Crashing past that point spends
more than it saves.
