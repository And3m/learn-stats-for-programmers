The dataset for this chapter is 900 grains from two visually similar varieties, described by seven
morphological measurements — area, perimeter, axis lengths, eccentricity, convex area and extent.
The task is to tell the varieties apart.

<h2 id="the-data">The data</h2>

The classes are balanced and the distributions overlap substantially. That overlap is the point:
perfectly separable data would teach nothing about the failure modes.

<h2 id="training">Training the tree</h2>

Here the workflow diverges sharply from chapters&nbsp;4 and&nbsp;5. Those chapters fitted on all
the data and reported goodness of fit. For a model this flexible, that would be meaningless — a
tree can drive training accuracy to 100% by memorising, so training accuracy measures nothing
except capacity.

The fix is a **held-out test set**: fit on one portion, evaluate on data the model has never seen.
Nothing that touches the test set may influence the model, including your choices about it.

<Callout title="Stratify the split">
  <p>
    <code>stratify=y</code> preserves the class proportions in both halves. Without it, a random
    split can leave one class over-represented in the test set by chance, and every metric shifts
    for reasons that have nothing to do with the model. It costs one keyword and should be the
    default for classification.
  </p>
</Callout>

<PythonCell label="Split, fit, evaluate">
{`from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier
from sklearn.metrics import accuracy_score, confusion_matrix, classification_report

X = grains.drop(columns=["variety"])
y = (grains["variety"] == "besni").astype(int)      # 1 = besni, 0 = keswani

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, random_state=7, stratify=y
)

print(f"train {len(X_train)} rows, test {len(X_test)} rows")
print(f"class balance preserved: train {y_train.mean():.3f}, test {y_test.mean():.3f}")

tree = DecisionTreeClassifier(max_depth=3, random_state=7)
tree.fit(X_train, y_train)

print()
print(f"training accuracy {accuracy_score(y_train, tree.predict(X_train)):.4f}")
print(f"test accuracy     {accuracy_score(y_test, tree.predict(X_test)):.4f}")

print()
print(confusion_matrix(y_test, tree.predict(X_test)))
print()
print(classification_report(y_test, tree.predict(X_test),
                            target_names=["keswani", "besni"], digits=4))`}
</PythonCell>

<h2 id="plotting">Plotting the tree</h2>

The reason to use a tree at all is that you can look at it. `plot_tree` renders the whole model:
each box shows the splitting rule, the impurity, how many training samples reached that node, and
the class distribution there.

<PythonCell label="The model, drawn">
{`from sklearn.tree import plot_tree, export_text

fig, ax = plt.subplots(figsize=(11, 6))
plot_tree(
    tree,
    feature_names=list(X.columns),
    class_names=["keswani", "besni"],
    filled=True,
    rounded=True,
    fontsize=7,
    ax=ax,
)
ax.set_title("Decision tree, max_depth = 3")

print(export_text(tree, feature_names=list(X.columns), decimals=2))`}
</PythonCell>

Reading a node: `major_axis <= 412.35` is the question; `gini = 0.48` is the impurity;
`samples = 630` is how many training rows reached it; `value = [315, 315]` is the class counts.
Colour intensity tracks purity, and the colour itself tracks the majority class.

<h2 id="reading-a-path">Following one observation down</h2>

The property that makes trees worth their limitations is that any single prediction can be
explained exactly — not approximated, not attributed, but replayed step by step.

<PythonCell label="Replaying one prediction">
{`sample_index = 4
sample = X_test.iloc[[sample_index]]
true_label = y_test.iloc[sample_index]

print("Observation:")
print(sample.T.rename(columns={sample.index[0]: "value"}).to_string())
print()

structure = tree.tree_
node = 0
step = 1
while structure.children_left[node] != structure.children_right[node]:
    feature = X.columns[structure.feature[node]]
    threshold = structure.threshold[node]
    value = sample[feature].iloc[0]
    goes_left = value <= threshold
    print(f"  step {step}: is {feature} ({value:.2f}) <= {threshold:.2f}?  "
          f"{'yes -> left' if goes_left else 'no  -> right'}")
    node = structure.children_left[node] if goes_left else structure.children_right[node]
    step += 1

counts = structure.value[node][0]
print()
print(f"  leaf reached: {int(structure.n_node_samples[node])} training samples, "
      f"class proportions {np.round(counts, 3)}")

probability = tree.predict_proba(sample)[0]
print(f"  predicted probabilities: keswani {probability[0]:.3f}, besni {probability[1]:.3f}")
print(f"  prediction: {'besni' if tree.predict(sample)[0] == 1 else 'keswani'}"
      f"   actual: {'besni' if true_label == 1 else 'keswani'}")`}
</PythonCell>

Notice what the predicted probability actually is: the class proportion among the training samples
that landed in that leaf. Nothing more sophisticated is happening. That is worth knowing, because
it means tree probabilities are coarse — a leaf with four training samples can only ever emit
0, 0.25, 0.5, 0.75 or 1.
