A single tree is unstable. Change a handful of training rows and the top split can change, and
everything below it changes with it. That instability is a weakness — and, counter-intuitively,
the thing that makes the ensemble work.

<h2 id="bagging">Bagging</h2>

**Bootstrap aggregating** is two steps:

1. Draw $B$ bootstrap samples — each the same size as the training set, sampled **with
   replacement**, so each contains roughly 63% of the unique rows with some repeated.
2. Fit a full, unpruned tree on each, and average their predictions (or take a majority vote).

The reason this works is a fact about variance. If you average $B$ independent estimates each with
variance $\sigma^2$, the average has variance $\sigma^2/B$. Averaging reduces variance while
leaving bias unchanged — so you deliberately use **high-variance, low-bias** base learners
(unpruned trees), and let the averaging clean up the variance.

The catch is the word *independent*. Trees grown on bootstrap samples of the same data are highly
correlated, especially if one feature dominates: every tree splits on it first and they all make
similar mistakes. Averaging correlated estimates helps much less.

<h2 id="feature-randomness">Feature randomness</h2>

This is the one idea that separates a random forest from plain bagging: **at every split,
consider only a random subset of the features.**

The default is $\sqrt{p}$ features for classification. It sounds like sabotage — deliberately
hiding the best feature from most splits — but it forces trees to explore different structures,
which decorrelates them, which is precisely what makes averaging effective again.

Individually the trees are worse. Collectively they are much better. That trade is the whole
insight.

Out-of-bag scoring is a genuinely nice property of bagged ensembles. Because each bootstrap sample
omits about 37% of the rows, every row can be scored by the trees that never saw it — a
validation estimate for free, without a separate holdout.

<h2 id="feature-importance">Feature importance, and its caveats</h2>

A forest can report how much each feature contributed, and this is one of the main reasons people
reach for them. It is also routinely over-read.

The default measure is **mean decrease in impurity**: total impurity removed by splits on that
feature, averaged over trees. It has two well-documented biases.

- It **favours high-cardinality features** — continuous variables and categoricals with many
  levels offer more candidate split points, so they win more often by chance.
- It **splits credit arbitrarily among correlated features**. If two features carry the same
  information, the forest uses whichever it happened to see, and each ends up looking half as
  important as the information really is.

**Permutation importance** avoids both. Shuffle one column in the *test* set, measure how much
performance drops, and repeat. It measures what the model actually relies on, computed on held-out
data.

<PythonCell label="Two importance measures, compared">
{`from sklearn.inspection import permutation_importance

forest = fitted["random forest (300)"]

impurity = pd.Series(forest.feature_importances_, index=X.columns)

    forest, X_test, y_test, n_repeats=15, random_state=7, scoring="accuracy"
)

comparison = pd.DataFrame({
    "impurity": impurity,
    "permutation": permutation,
    "perm_sd": result.importances_std,
}).sort_values("permutation", ascending=False)

print(X.corr().round(2).to_string())

fig, ax = plt.subplots()
order = comparison.index[::-1]
positions = np.arange(len(order))
ax.barh(positions - 0.2, comparison.loc[order, "impurity"], height=0.4, label="impurity")
ax.barh(positions + 0.2, comparison.loc[order, "permutation"], height=0.4, label="permutation")
ax.set_yticks(positions)
ax.set_yticklabels(order)
ax.set_xlabel("importance")
ax.set_title("Two measures disagree when features are correlated")
ax.legend()`}
</PythonCell>

The features here are heavily correlated — area, perimeter, convex area and the axis lengths all
measure aspects of the same physical size. The two importance measures disagree, and the
disagreement is informative: it tells you that no individual ranking is trustworthy, because the
underlying information is shared.

<Callout title="Importance is not causation, and not even effect size" variant="pitfall">
  A high importance means the model leaned on that feature. It does not mean the feature causes
  the outcome, nor that intervening on it would change anything, nor that it is irreplaceable —
  drop it and a correlated feature will often absorb the work with almost no loss. Treat
  importance as a description of the model, not of the world.
</Callout>

<h2 id="when-to-use">When to reach for a forest</h2>

**Reach for one when** you need strong tabular predictive performance with minimal tuning; the
relationships are non-linear or full of interactions; features are on wildly different scales
(trees do not care); or you want a solid baseline quickly.

**Reach for something else when** you must explain individual decisions to a regulator or a
customer — a single shallow tree or a logistic regression is auditable in a way an ensemble is
not; you need calibrated probabilities without extra work; the relationship is genuinely linear,
where regression will be both better and simpler; or you need to extrapolate beyond the training
range, which trees fundamentally cannot do — every prediction is an average of training values
that were actually observed.

That last limitation is worth emphasising. Ask a forest trained on grains of 20,000–140,000 units
of area about a grain of 400,000, and it will return the average of its most extreme leaf. It
cannot say "bigger than anything I have seen." A linear model can.
