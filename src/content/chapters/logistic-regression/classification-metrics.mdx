A logistic model outputs a probability. Turning that into a decision requires a threshold, and
evaluating that decision requires metrics. Choosing the wrong metric is how models that do nothing
useful get shipped.

<h2 id="confusion-matrix">The confusion matrix</h2>

Every binary prediction lands in one of four cells:

| | Predicted negative | Predicted positive |
| --- | --- | --- |
| **Actually negative** | True negative (TN) | **False positive (FP)** — type I error |
| **Actually positive** | **False negative (FN)** — type II error | True positive (TP) |

Everything else in this lesson is a ratio of these four numbers. The two off-diagonal cells are
the ones that matter, and the crucial point is that **they usually have very different costs**.

For loan defaults: a false positive means declining a borrower who would have repaid — lost
revenue. A false negative means approving a borrower who defaults — a written-off loan. If the
second costs ten times the first, any metric that treats them equally is answering the wrong
question.

<PythonCell label="The confusion matrix, spelled out">
{`import numpy as np
import pandas as pd
import statsmodels.formula.api as smf
from sklearn.metrics import confusion_matrix

loans = pd.read_csv("loan-defaults.csv")
model = smf.logit(
    "defaulted ~ credit_score + debt_to_income + months_employed + prior_defaults",
    data=loans,
).fit(disp=0)

actual = loans["defaulted"].to_numpy()
probability = model.predict(loans).to_numpy()
predicted = (probability >= 0.5).astype(int)

tn, fp, fn, tp = confusion_matrix(actual, predicted).ravel()

print("                  predicted no   predicted yes")
print(f"actually no     {tn:>13,} {fp:>15,}")
print(f"actually yes    {fn:>13,} {tp:>15,}")
print()
print(f"true negatives  {tn:>5,}  correctly approved")
print(f"false positives {fp:>5,}  declined, would have repaid")
print(f"false negatives {fn:>5,}  approved, then defaulted")
print(f"true positives  {tp:>5,}  correctly declined")`}
</PythonCell>

<h2 id="precision-recall">Precision and recall</h2>

$$
\text{precision} = \frac{TP}{TP + FP}
\qquad
\text{recall} = \frac{TP}{TP + FN}
$$

**Precision** answers: *of the cases I flagged, how many were real?* It is the metric to optimise
when acting on a positive prediction is expensive — sending an engineer to investigate, blocking a
transaction, contacting a customer.

**Recall** (also called sensitivity, or the true positive rate) answers: *of the real cases, how
many did I catch?* It is the metric to optimise when missing a positive is expensive — undetected
fraud, a missed diagnosis, an outage nobody noticed.

They trade off against each other, and the trade is controlled by the threshold. Flag everything
and recall hits 1 while precision collapses to the base rate. Flag only the most certain case and
precision may be 1 while recall is near zero.

Two more, less often needed but worth naming: **specificity** is $TN/(TN+FP)$, the recall of the
negative class; **negative predictive value** is $TN/(TN+FN)$, the precision of the negative class.

<h2 id="f1">F1 and the trade-off</h2>

When both errors matter and you need a single number, F1 is the harmonic mean:

$$
F_1 = 2 \cdot \frac{\text{precision} \cdot \text{recall}}{\text{precision} + \text{recall}}
$$

The harmonic mean is used rather than the arithmetic mean because it punishes imbalance. A model
with precision 1.0 and recall 0.02 has an arithmetic mean of 0.51, which flatters it enormously —
and an F1 of 0.039, which is honest.

If you know the relative costs, $F_\beta$ generalises this: $\beta > 1$ weights recall more
heavily, $\beta < 1$ weights precision.

<PythonCell label="Every metric, from the four counts">
{`from sklearn.metrics import classification_report

accuracy = (tp + tn) / (tp + tn + fp + fn)
precision = tp / (tp + fp)
recall = tp / (tp + fn)
specificity = tn / (tn + fp)
npv = tn / (tn + fn)
f1 = 2 * precision * recall / (precision + recall)

print(f"accuracy     {accuracy:.4f}   of all predictions, how many were right")
print(f"precision    {precision:.4f}   of those flagged, how many defaulted")
print(f"recall       {recall:.4f}   of actual defaults, how many were flagged")
print(f"specificity  {specificity:.4f}   of actual repayers, how many were cleared")
print(f"NPV          {npv:.4f}   of those approved, how many repaid")
print(f"F1           {f1:.4f}   harmonic mean of precision and recall")

print()
print("scikit-learn agrees:")
print(classification_report(actual, predicted, target_names=["repaid", "defaulted"], digits=4))`}
</PythonCell>

<h2 id="accuracy-trap">The accuracy trap</h2>

Here is the number that should end any argument about using accuracy on imbalanced data.

The default rate is about 21%. A model that ignores every input and predicts "no default" for
every single loan is right 79% of the time. The fitted logistic regression achieves about 81%.

Two percentage points. On accuracy alone, a model that genuinely discriminates between borrowers
looks barely distinguishable from one that does nothing at all.

<PythonCell label="The trap, demonstrated">
{`from sklearn.metrics import roc_auc_score

base_rate = actual.mean()
always_no = np.zeros_like(actual)

print(f"base rate (default): {base_rate:.4f}")
print()
print(f"{'strategy':<28}{'accuracy':>10}{'recall':>9}{'precision':>11}{'F1':>8}{'AUC':>8}")

def row(name, preds, scores=None):
    acc = (preds == actual).mean()
    tp_ = ((preds == 1) & (actual == 1)).sum()
    fp_ = ((preds == 1) & (actual == 0)).sum()
    fn_ = ((preds == 0) & (actual == 1)).sum()
    rec = tp_ / (tp_ + fn_) if tp_ + fn_ else 0.0
    prec = tp_ / (tp_ + fp_) if tp_ + fp_ else 0.0
    f = 2 * prec * rec / (prec + rec) if prec + rec else 0.0
    auc = roc_auc_score(actual, scores) if scores is not None else float("nan")
    print(f"{name:<28}{acc:>10.4f}{rec:>9.4f}{prec:>11.4f}{f:>8.4f}{auc:>8.4f}")

row("always predict 'no'", always_no, np.zeros_like(probability))
row("logistic model @ 0.50", predicted, probability)
row("logistic model @ 0.25", (probability >= 0.25).astype(int), probability)

print()
print("Accuracy separates these strategies by ~2 points.")
print("Recall separates them by an enormous margin - and AUC, which needs")
print("no threshold at all, shows the model has real discriminating power")
print("that the always-no baseline (AUC 0.5) does not.")`}
</PythonCell>

<Callout title="What to do instead" variant="warning">
  On imbalanced data, report the confusion matrix and at least one threshold-free measure. AUC
  (lesson&nbsp;5.4) summarises ranking quality across all thresholds. Precision-recall curves are
  often more informative still when the positive class is rare, because they ignore the large and
  uninformative true-negative count entirely. Accuracy belongs in a report only alongside the
  base rate it must be compared against.
</Callout>
